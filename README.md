# PublishPDF

Turns company report PDFs (quarterly results, investor presentations, annual reports) into
validated, AI-readable web pages served on the client's own subdomain.

- Plan and decisions: [PLAN.md](PLAN.md)
- Architecture: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Environment template: [.env.example](.env.example)
- Report JSON Schema: [backend/app/schema/report.schema.json](backend/app/schema/report.schema.json)
- Extraction accuracy on the test corpus: [corpus/ACCURACY.md](corpus/ACCURACY.md)

## Run it (macOS, no Docker)

One-time setup:

```bash
brew install postgresql@16 tesseract
```

```bash
cp .env.example .env
```

In `.env`, set `APP_SECRET_KEY` (`cd backend && uv run python -m app.cli gen-secret`), point both
database URLs at `localhost:54329` with the dev passwords (`owner_dev_pw` / `app_dev_pw`), and for
local use set `APP_ENV=development`, `PUBLIC_SCHEME=http`, `PUBLIC_PORT_SUFFIX=:8080`,
`TLS_MODE=off`, `PREVIEW_URL_PATTERN={tenant_slug}.preview.localhost` and a placeholder
`DISCLAIMER_DEFAULT_TEXT`.

Then start everything (database, API, worker, public sites, dashboard) with one command:

```bash
scripts/dev.sh
```

Optional demo data (a workspace with the synthetic sample reports, one already published):

```bash
cd backend && uv run python scripts/make_corpus.py && uv run python -m app.cli seed-demo
```

## The flow

1. **Sign in** with your email and a 6-digit code (no password). New users name their company and get their own workspace. Two-factor (authenticator app) is optional in Settings.
2. **Upload**: drop a PDF on the Reports page. Company, report type, fiscal year, period, currency and unit are detected from the PDF; you confirm them.
3. **Extract & verify**: live progress ("reading page 37 of 120"), then independent validation agents (source trace, a second PDF parser, visual OCR re-read, arithmetic, cross-table consistency, periods & units, the generated web page, completeness, human review). Each figure shows how many agents confirmed it. Anything doubtful must be resolved side by side with the PDF.
4. **Design**: take the look from your website, a colour palette, or a brand PDF/images; fine-tune; preview your actual report live.
5. **Review** the generated page next to the PDF (desktop/mobile), plus checks and extracted data.
6. **Approve & publish**; roll back any time.

## What it does

1. **Upload** a PDF with company, report type, fiscal year, period, currency and unit. The file is
   stored unchanged with its SHA-256.
2. **Extract**: text layer where usable, local OCR (Tesseract) for scanned pages; tables as cells
   with merged headers; charts (vector data labels extracted, images marked "not extracted");
   headers/footers removed; Indian and international number formats, brackets, dashes, dates,
   periods.
3. **Schema**: one JSON document per version, validated against the published JSON Schema.
   Every figure keeps its raw string, value, unit, currency, period, row/column labels, page,
   bounding box, method and confidence. Text never contains a digit outside a figure.
4. **Validate** (publishing is blocked while any blocking issue is open): traceability,
   independent visual re-reading, arithmetic (totals, balance sheet, % changes), period/unit
   consistency, the generated page itself, completeness, low-confidence OCR.
5. **Review**: side-by-side PDF region vs extracted value with Confirm / Edit / Not a figure, all
   audited; reviewer flags and comments; desktop/mobile preview synced with the PDF.
6. **Publish**: immutable versions, one-click rollback, drafts from any version.
7. **Serve**: static HTML (no JavaScript needed), Markdown, JSON and CSV of figures, schema.org
   JSON-LD, sitemap, robots.txt (3 AI-crawler presets), llms.txt, latest/archive pages, canonical
   tags, link to the PDF and disclaimer on every page.
8. **Theme**: match website / custom editor / reference URLs or images → one token set, contrast
   enforced, identical HTML in every theme.
9. **Custom subdomain**: CNAME + TXT verification, provider guides, IT email, automatic checks,
   on-demand TLS via Caddy, monitoring and alerts, preview → custom 301.
10. **Analytics**: per-tenant GA4 (consent banner on by default), crawler/visit stats from our
    own logs.

## Status

All six phases are implemented and tested (187 automated tests). Honest limits:

| Area | State |
| --- | --- |
| Test corpus | **Synthetic** PDFs generated by `backend/scripts/make_corpus.py` (not real filings). Accuracy on real reports is unmeasured until you add PDFs to `corpus/real/` with a `*.truth.json` |
| OCR | Tesseract only. The second "independent" reading of OCR pages is a differently-configured Tesseract crop read, not a second engine; a PaddleOCR/cloud adapter is the planned upgrade (PLAN D2/D3) |
| TLS | Caddy config is in `infra/caddy/`; the state machine is tested with a fake resolver and TLS probe. A real certificate has not been issued (needs a server and `PLATFORM_TARGET_HOSTNAME` DNS) |
| Email | Console backend in development; SMTP wired but untested |
| Storage | Local filesystem in development; S3 backend written but untested |
| LLM assist | Off by default; tested with a fake (adversarial) model only — no live model calls were made |
| Enterprise SSO | Not built (later phase) |
| Placeholders | Platform domain (`publishpdf.ai` assumed), disclaimer text, limits, TXT prefix, CA list — see `.env.example` |
